## Architecture

**Index Strategy:**
- **Type:** B-tree indexes on foreign key columns (standard choice for equality lookups)
- **Placement:** Indexes on child table FK columns (where JOIN happens)
- **Concurrency:** `CREATE INDEX CONCURRENTLY` to avoid locking (if Supabase allows)
- **Naming:** `idx_{table}_{column}` convention (e.g., `idx_project_schedules_project_id`)

**Baseline Methodology:**
- Use `EXPLAIN ANALYZE` for accurate execution plans
- Test with realistic data volume (not empty tables)
- Multiple runs to avoid disk cache bias
- Cold cache: DISCARD PLANS + RESTART PostgreSQL if needed
- Document hardware context (Supabase compute tier)

**SLA Approach:**
- Targets based on EPIC 7 KPI requirements (Kanban, Dashboard)
- p95 latency used (not average, not p99)
- Per-query-type SLAs (dashboard ≠ report queries)
- Baseline → post-EPIC-8.2 tracking

## Dev Notes

**Critical Information for @dev:**

1. **Index Names Convention:** Use `idx_{table}_{column}` (e.g., `idx_project_schedules_project_id`)
   - Helps with future debugging + maintenance
   - Supabase auto-generates names if omitted; we want explicit names

2. **Concurrent Index Creation:** If Supabase supports it, use `CREATE INDEX CONCURRENTLY`
   - Allows read/write traffic during index creation (no locking)
   - Takes longer but zero downtime
   - Check Supabase docs for availability

3. **Performance Measurement Strategy:**
   - **Cold cache measurement:** Run `DISCARD PLANS; RESTART;` before baseline query
   - **Realistic data volume:** Measure with actual project count (not test data)
   - **p95 latency:** Use percentile 95th, not average (captures user experience)
   - **Document hardware:** Note Supabase compute tier + PostgreSQL version

4. **SLA Targets Rationale:**
   - **Dashboard <100ms:** User expects interactive response (Kanban sorting, filtering)
   - **Kanban <150ms:** Card rendering needs snappy data load
   - **List <200ms:** Standard CRUD list response time
   - **Report <500ms:** Large datasets allowed longer

5. **Future EPIC 8.2 Context:**
   - This baseline will be compared against post-optimization metrics
   - Document CURRENT execution plans (EXPLAIN) for comparison
   - Identify N+1 queries NOW for EPIC 8.2 JOINs refactor
