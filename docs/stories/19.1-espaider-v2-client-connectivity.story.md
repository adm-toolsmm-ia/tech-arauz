## Goal

Create the minimum viable HTTP client for Espaider API v2 and validate authenticated connectivity using the contract documented in EPIC 19.

This story proves the integration boundary and prevents the team from implementing ETL on top of a wrong transport assumption.

Do assume:

- initial call is `POST /ConsultarRegistros`
- token and identifier go in headers
- pagination follow-up is `GET /ConsultarRegistrosComChave`

Do not assume:

- body token like v1
- `ListaCampos`
- `ListaURLFilhos`
- reuse of `exportarDados()` as-is

## Architecture Notes

Recommended structure:

```text
src/integrations/espaider-v2/
  config.ts
  client.ts
  types.ts
```

Recommended client responsibilities:

- build header-based authenticated requests
- send filter payload JSON for initial POST
- execute pagination GET using returned key or URL
- classify HTTP/network/timeout errors
- return sanitized diagnostics to callers

Recommended non-goals for this story:

- full ETL
- persistence
- child dataset processing
- frontend log integration
