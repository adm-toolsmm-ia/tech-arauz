# Story 19.8: Espaider v2 Rollout, Rollback and v1 Decommission

**EPIC:** 19 - Espaider v2 Sync Migration
**Story ID:** 19.8
**Status:** READY
**Assignee:** @architect + @qa + @devops
**Priority:** HIGH
**Effort:** 1-2 days
**Depends on:** 19.7

---

## Goal

Document and validate the rollout path for v2, the rollback path to v1, and the controlled decommission criteria for the legacy flow.

---

## Context for Implementation

This story is not optional ceremony. EPIC 19 explicitly requires:

- controlled migration
- safe shutdown of v1
- rollback plan

Without this story, the project may have working code but still be operationally unsafe.

---

## Acceptance Criteria

- [ ] Rollout sequence is documented step by step
- [ ] Rollback sequence is documented step by step
- [ ] v1 shutdown criteria are explicit and measurable
- [ ] Production validation checklist exists
- [ ] Post-cutover monitoring checklist exists
- [ ] Known risks and fallback triggers are documented
- [ ] File lists in EPIC 19 and story files are updated

---

## Required Deliverables

- rollout checklist
- rollback checklist
- go/no-go criteria
- smoke-test checklist
- criteria for decommissioning v1

Recommended go/no-go examples:

- connectivity stable
- incremental sync stable
- no duplicate creation on replay
- frontend logs visible
- quarantine working
- rollback switch tested
