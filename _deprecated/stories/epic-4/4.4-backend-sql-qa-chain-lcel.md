## Objetivo

Criar LCEL chain para SQL QA que classifica intent, gera SQL, valida, executa contra Supabase, formata resposta em PT-BR, com 5 spans de observabilidade e enforcement de budget.

---

## Como Usuário

Como chat frontend,
quero que o agente AI possa executar queries SQL seguras contra o banco de dados,
para que os usuários possam fazer perguntas em linguagem natural e receber dados reais (não hallucinated), junto com rastreamento completo de execução e custos.

---

## Contexto

**Situação atual:**
- Story 4.2 criou factory de LLM + SQL validator
- Story 4.3 criou session service + endpoints de chat
- Story 4.1 criou tabelas de chat, observabilidade, budgets

**Mudança necessária:**
- LCEL chain em `services/ai/app/chains/sql_qa.py` com 5 passos sequenciais:
  1. **Intent Classification** (modelo fast: gpt-4o-mini ou claude-3-haiku)
     - Classifica input em: data_query, chit_chat, out_of_scope
  2. **SQL Generation** (modelo do agente configurado)
     - Gera SQL bruto baseado em intent + schema context + histórico
  3. **SQL Validation** (via `sql_validator.validate_sql()`)
     - Valida e transforma SQL (LIMIT, WHERE tenant_id)
  4. **Query Execution** (Supabase PostgREST via service role)
     - Executa SELECT contra banco de dados
  5. **Response Formatting** (modelo do agente)
     - Formata resultado em prosa PT-BR

- Cada passo é um span LangSmith (5 spans por execução)
- Budget enforcement: se `agent_budgets.limit_usd` < custo estimado, rejeita
- Error handling: SQL parse errors, API failures, execution timeouts, budget exceeded

## Critérios de Aceite

### LCEL Chain (chains/sql_qa.py)

- [ ] Função `build_sql_qa_chain(agent_config: dict, message_history: list[dict]) → Runnable`
  - Retorna um LCEL Runnable que aceita: `{ input: str }`
  - Retorna: `{ answer: str, sql_query?: str, row_count?: int, tokens_used: int, cost_usd: float }`
  - Message history é injetado no prompt como contexto
  - Agent config contém: provider, model_id, temperature, max_tokens, system_prompt

- [ ] Função `run_sql_qa(agent_id: str, tenant_id: str, session_id: str, user_message: str, message_history: list[dict], supabase: AsyncClient) → SQLQAResult`
  - Executa o chain com message history e session context
  - Retorna SQLQAResult com: answer, sql_query, row_count, tokens_used, cost_usd, duration_ms, trace_url, error
  - Envolve toda execução em `with_run_context()` para tracing
  - Atualiza budget antes de executar (levanta erro se budget insuficiente)
  - Retorna gracefully em caso de erro (não lança exception, retorna error_message em SQLQAResult)

- [ ] Classe `SQLQAResult(BaseModel)`
  - answer: str (resposta em PT-BR)
  - sql_query: Optional[str] (SQL executado, se data_query)
  - row_count: Optional[int] (número de linhas retornadas)
  - tokens_used: int (total de tokens na chain)
  - cost_usd: float (custo total)
  - duration_ms: int (latência total)
  - trace_url: Optional[str] (LangSmith URL)
  - error: Optional[str] (se houve erro, mensagem aqui)
  - error_code: Optional[str] (classification: budget_exceeded, sql_error, execution_error, etc.)

### 5-Step LCEL Chain

**Step 1: Intent Classifier (Span: intent_classify)**
```
Model: gpt-4o-mini (fast, cheap)
Input: user_message + system_prompt
Output: { intent: "data_query" | "chit_chat" | "out_of_scope" }

Prompt:
```
You are a classifier. Analyze the user message and classify it:
- data_query: Question about project data (schedules, deliveries, budgets, etc.)
- chit_chat: Casual conversation, greetings, off-topic
- out_of_scope: Requests for sensitive data, system access, etc.

User message: {user_message}

Classification (only respond with: data_query, chit_chat, or out_of_scope):
```
```

**Step 2: SQL Generator (Span: sql_generate) — Only if intent is data_query**
```
Model: Agent's configured model (gpt-4o, claude-3, etc.)
Input: user_message + message_history + schema_context
Output: { sql_query: str }

Prompt:
```
You are a SQL expert. Generate a SELECT query to answer the user's question.

Database schema:
- projects (id, name, status, ...)
- project_schedules (project_id, start_date, end_date, duration_days, ...)
- project_deliveries (project_id, delivered_date, status, ...)
- project_requirements (project_id, requirement, status, ...)
- project_histories (project_id, event, timestamp, ...)
- project_budgets (project_id, total_budget, spent, ...)

Important:
- ONLY SELECT queries allowed
- Always filter by tenant_id
- Limit results to avoid large datasets
- Use proper JOINs for related data

Conversation history:
{history}

User message: {user_message}

SQL Query:
```
```

**Step 3: SQL Validator (Span: sql_validate)**
```
Function: sql_validator.validate_sql(raw_sql, tenant_id)
Input: { sql_query: str }
Output: { clean_sql: str } or raises SQLValidationError

Side effects:
- Injects LIMIT 100
- Injects WHERE tenant_id = X
- Validates against table whitelist
```

**Step 4: Query Executor (Span: query_execute)**
```
Input: { clean_sql: str, tenant_id: str }
Output: { rows: list[dict], row_count: int }

Code:
```python
response = await supabase.postgrest.rpc(
    "sql",  # or direct .table().select()
    {"query": clean_sql}
).execute()

rows = response.data if response.data else []
row_count = len(rows) if isinstance(rows, list) else 0
```
```

**Step 5: Response Formatter (Span: response_format)**
```
Model: Agent's configured model
Input: user_message + query_result
Output: { answer: str } (PT-BR prose)

Prompt:
```
You are a helpful assistant. The user asked a question, and here is the data:

User question: {user_message}

Data returned from database:
{json.dumps(rows, indent=2)}

Provide a clear, friendly response in Portuguese (PT-BR) summarizing the data.
Keep it concise (2-3 sentences).
```
```

### Error Handling & Graceful Degradation

- [ ] **Intent Classification Error**: Fallback to "chit_chat" (don't attempt SQL)
  - Return: "Desculpe, não consegui entender sua pergunta. Pode reformular?"

- [ ] **SQL Generation Error**: LLM refused or failed
  - Return: "Não consegui gerar uma query para essa pergunta. Tente ser mais específico."

- [ ] **SQL Validation Error**: Table not allowed, DML, syntax error
  - Return: "A query não é segura. Motivo: {error_code}"
  - Includes: error_code (parse_error, blocked_table, mutation_blocked, no_select)

- [ ] **Query Execution Error**: Timeout, database error, etc.
  - Return: "Erro ao executar a query. Tente novamente."
  - Logs error_code: execution_error, timeout, database_error

- [ ] **Budget Exceeded**: Agent has exceeded monthly limit
  - Return: "Orçamento mensálo excedido para este agente."
  - error_code: budget_exceeded

- [ ] **Response Formatting Error**: LLM failed to format
  - Fallback to raw data: "Resultados: {json.dumps(rows)}"

### Observability & Tracing

- [ ] **LangSmith Spans** (5 total per execution):
  1. `intent_classify` (llm.call) — intent classification
  2. `sql_generate` (llm.call) — SQL generation
  3. `sql_validate` (tool.call) — SQL validation
  4. `query_execute` (tool.call) — Query execution
  5. `response_format` (llm.call) — Response formatting

- [ ] **Metadata captured per span:**
  - input.preview: User input (redacted)
  - output.preview: Result (truncated, PII redacted)
  - latency_ms: Span duration
  - model: LLM model name
  - tokens_used: Token count (if available)
  - cost_usd: Cost of step
  - error: Error message (if error)

- [ ] **Run context:**
  - run_id: UUID per run
  - trace_id: UUID per trace
  - session_id: Chat session ID
  - agent_id: Agent being executed
  - tenant_id: Tenant isolation

### Budget Enforcement

- [ ] **Pre-flight check:**
  ```python
  # Before executing chain
  bm = get_budget_manager()
  bm.assert_remaining(session_id=session_id, user_id=user_id, agent_id=agent_id)
  # Raises BudgetExceededError if insufficient
  ```

- [ ] **Cost tracking:**
  - Each LLM call contributes to cost
  - SQL execution is free (Supabase)
  - Total cost = sum(LLM costs)
  - Stored in SQLQAResult.cost_usd

- [ ] **Post-execution charge:**
  ```python
  bm.charge(cost_usd, session_id=session_id, user_id=user_id, agent_id=agent_id)
  ```

```python
@router.post("/agents/{agent_id}/chat")
async def chat_with_agent(...):
    # ... existing code to create session ...

    # Call SQL QA chain (Story 4.4)
    result = await run_sql_qa(
        agent_id=agent_id,
        tenant_id=tenant_id,
        session_id=session["id"],
        user_message=request_body.message,
        message_history=history,

    # Persist turn with result
    user_msg_id, asst_msg_id = await persist_turn(
        session_id=session["id"],

    return ChatResponse(
        session_id=session["id"],
