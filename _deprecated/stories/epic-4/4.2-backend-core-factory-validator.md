## Objetivo

Criar infraestrutura core para LLM multi-provider (OpenAI, Anthropic, Google Gemini, Azure OpenAI) com factory pattern, e validador SQL seguro com bloqueio de DML/DDL, LIMIT injection, e tenant_id filtering via AST.

---

## Como Usuário

Como desenvolvedor de backend,
quero ter uma factory pattern para instanciar LLM clients de múltiplos providers,
e um validador SQL robusto que bloqueia ataques de injection e DML/DDL,
para que eu possa construir chains LCEL seguras que consultam banco de dados sem risco de data loss ou unauthorized access.

---

## Contexto

**Situação atual:**
- Story 4.1 (Migration 042) criou 11 tabelas de chat, observabilidade, budgets, tools, context
- Não há factory pattern para LLM providers
- Não há validador SQL — código poderia aceitar qualquer SQL bruto

**Mudança necessária:**
- Factory em `services/ai/app/llm/factory.py` que mapeia (provider, model_id) → BaseChatModel
- Validador em `services/ai/app/chains/sql_validator.py` que:
  - Parse SQL bruto com sqlglot AST
  - Whitelist 6 tabelas (projects, project_schedules, project_deliveries, project_requirements, project_histories, project_budgets)
  - Bloqueia DML/DDL (INSERT, UPDATE, DELETE, CREATE, etc.)
  - Injeta LIMIT 100 (configurável até 500) via AST
  - Injeta `WHERE tenant_id = '{tenant_id}'` via AST (NUNCA string concat)
  - Retorna clean SQL ou erro com code específico
- Config.py + pyproject.toml estendidos para novas dependências

## Critérios de Aceite

### Factory Pattern (llm/factory.py)

- [ ] Função `get_llm(provider: str, model_id: str, **kwargs) → BaseChatModel`
  - Provider mappings:
    - `openai` → `ChatOpenAI(model=model_id, api_key=env[OPENAI_API_KEY])`
    - `anthropic` → `ChatAnthropic(model=model_id, api_key=env[ANTHROPIC_API_KEY])`
    - `google_gemini` → `ChatGoogleGenerativeAI(model=model_id, api_key=env[GOOGLE_API_KEY])`
    - `azure_openai` → `AzureChatOpenAI(model=model_id, api_key=env[AZURE_OPENAI_API_KEY])`
  - Suporta kwargs customizados: temperature, max_tokens, top_p, etc.
  - Valida provider contra lista permitida (levanta `LLMProviderError` se desconhecido)
  - Valida API keys (levanta `LLMProviderError` se env var vazia/missing)

- [ ] Classe `LLMProviderError(Exception)`
  - Herda de Exception
  - Armazena provider, model_id, error_detail

- [ ] Imports corretos:
  - `from langchain_openai import ChatOpenAI`
  - `from langchain_anthropic import ChatAnthropic`
  - `from langchain_google_genai import ChatGoogleGenerativeAI`
  - `from langchain_openai import AzureChatOpenAI`
  - `from langchain_core.language_models import BaseChatModel`

### SQL Validator (chains/sql_validator.py)

- [ ] Função `validate_sql(raw_sql: str, tenant_id: str) → str`
  - Retorna clean SQL com LIMIT injetado e WHERE tenant_id = X
  - Levanta `SQLValidationError` se falha
  - Parsing via `sqlglot.parse_one()` (AST-based)

- [ ] Classe `SQLValidationError(Exception)`
  - Armazena: error_code (parse_error, blocked_table, mutation_blocked, no_select), message, raw_sql
  - error_code pode ser usado por frontend para UX específico

- [ ] Whitelist de tabelas:
  ```python
  ALLOWED_TABLES = frozenset({
      'projects',
      'project_schedules',
      'project_deliveries',
      'project_requirements',
      'project_histories',
      'project_budgets',
  })
  ```

- [ ] Validações executadas em sequência:
  1. **Parse SQL**: `sqlglot.parse_one(raw_sql, dialect='postgres')`
     - Se falha → `SQLValidationError(error_code="parse_error", ...)`

  2. **Type check**: Validar que statement é SELECT
     - Se é INSERT/UPDATE/DELETE/CREATE/DROP/ALTER/TRUNCATE → `SQLValidationError(error_code="mutation_blocked", ...)`
     - Se não é SELECT → `SQLValidationError(error_code="no_select", ...)`

  3. **Table whitelist**: Validar que TODAS as tabelas referenciadas estão em ALLOWED_TABLES
     - Extrair via `ast.find_all(sqlglot.expressions.Table)`
     - Ignorar tabelas entre parênteses (alias temporário)
     - Se tabela bloqueada → `SQLValidationError(error_code="blocked_table", table_name=..., ...)`

  4. **Inject LIMIT**: Via `ast.limit = sqlglot.expressions.Limit(expression=sqlglot.expressions.Literal.number(100))`
     - Configurável via setting: `SQL_QA_DEFAULT_LIMIT = 100` (em config.py)
     - Max permitido: `SQL_QA_MAX_LIMIT = 500` (em config.py)
     - Se SELECT já tem LIMIT, usar o MENOR entre (existente, DEFAULT)

  5. **Inject WHERE tenant_id**: Via AST manipulation (NUNCA f-string/string concat)
     - Buscar `ast.where` existente
     - Criar novo AND: `ast.where = sqlglot.and_(ast.where, sqlglot.parse_one(f"tenant_id = '{tenant_id}'"))`
     - Ou usar `sqlglot.expressions.Where()` + `expressions.EQ()`

  6. **Return clean SQL**: `ast.sql(dialect='postgres')`

- [ ] Error handling:
  - sqlglot.ParseError → `SQLValidationError(error_code="parse_error", ...)`
  - Qualquer exception não prevista → loga e re-raise como `SQLValidationError`

- [ ] Constants e configuração:
  ```python
  ALLOWED_TABLES = frozenset({...})
  BLOCKED_STATEMENT_TYPES = frozenset({'insert', 'update', 'delete', 'create', 'drop', 'alter', 'truncate'})
  ```

### test_sql_validator.py

```python
def test_validate_sql_basic_select():
    sql = "SELECT * FROM projects WHERE id = '123'"
    clean = validate_sql(sql, tenant_id="tenant-abc")
    assert "LIMIT 100" in clean
    assert f"tenant_id = 'tenant-abc'" in clean

def test_validate_sql_rejects_insert():
    sql = "INSERT INTO projects (name) VALUES ('test')"
    with pytest.raises(SQLValidationError) as exc:
        validate_sql(sql, tenant_id="tenant-abc")
    assert exc.value.error_code == "mutation_blocked"

def test_validate_sql_rejects_blocked_table():
    sql = "SELECT * FROM users"  # users não está em ALLOWED_TABLES
    with pytest.raises(SQLValidationError) as exc:
        validate_sql(sql, tenant_id="tenant-abc")
    assert exc.value.error_code == "blocked_table"

def test_validate_sql_parse_error():
    sql = "SELECT * FROM projects WHERE id = "  # SQL malformado
    with pytest.raises(SQLValidationError) as exc:
        validate_sql(sql, tenant_id="tenant-abc")
    assert exc.value.error_code == "parse_error"

def test_validate_sql_existing_limit_honored():
    sql = "SELECT * FROM projects LIMIT 10"
    clean = validate_sql(sql, tenant_id="tenant-abc")
    assert "LIMIT 10" in clean  # Usa menor: 10 vs 100

def test_validate_sql_tenant_isolation():
    sql = "SELECT * FROM projects"
    clean = validate_sql(sql, tenant_id="tenant-xyz")
    assert f"tenant_id = 'tenant-xyz'" in clean
```
