# 14.1 Atualização de Identidade Visual (Strict Reality Mode / AIOX Orchestrated)

## Goal
Aplicar um refinamento de design visual imediato e de altíssimo impacto para a **apresentação da diretoria de amanhã**, consumindo **ESTRITAMENTE** os ativos reais fornecidos pela equipe de marketing. 
**Regra de Ouro (Aria & Uma):** Zero componentes novos. Zero regras CSS "mágicas" e hardcoded. O sistema deve permanecer escalável sob a arquitetura existente.

## Contexto e Restrições para o Agente Gemini
- **Fonte ÚNICA da Verdade:** A pasta `docs/temp/Layout/` contém todos os assets de marketing reais do cliente. 
- **Atomic Design & Tokenization (@ux-design-expert):** O agente DEVE operar sob as regras de *Uma* (fase 3: Tokenize). O Gemini usará a API de `Vision` nos arquivos `.png` (`Logo Transparente/`, `PATTERN PNG/`, `SIMBOLO/` e `Icones/`) para extrair e gerar tokens arquitetônicos precisos (ex: HEX/RGB de primárias, secundárias, background).
- **Proibição de 'Alucinação' Visual:** O agente **não deve inventar** cores complementares, sombras ou fontes ausentes do material. Extrapolar o manual reduzirá a ROI da intervenção.
- **Engenharia e Arquitetura Base AIOX (@architect):** 
  1. `tailwind.config.ts` e globais: Use a abordagem *ZERO HARDCODED VALUES*. Todo CSS deve ser amarrado em `theme.extend.colors` e lido via classes globais predefinidas, obedecendo ao suporte Nativo Light Mode / Dark Mode.
  2. Atualize assets reais (em `public/`) manipulando apenas os vetores e bitmaps originais do Logo e Favicon, sem modificar o componente `<Logo />` ou `layout.tsx` a não ser pelas strings dos caminhos.
- **ZERO REESCRITA ESTRUTURAL (UX Intocada):** Respeite o fluxo atual. Não mexa em `padding`, `margin`, `layout modules` ou behaviour UI. Apenas tokens visuais e color styling.

## Tasks Executáveis (Padrão AIOX / Pipeline)
- [ ] **Task 1: Fase UX - Tokenize de Precisão Estrita (Vision)** → Analise os pixels das imagens `.png` do cliente. Extraia os *Design Tokens* base e os exponha.
- [ ] **Task 2: Fase Arquitetura - Injeção no State / Theme** → Alimente as variáveis base (`tailwind.config.ts`, `--primary`, `--secondary`, etc.) com as cores puras relativas ao manual.
- [ ] **Task 3: Fase Assets - Integração de Marca** → Use os arquivos reais mapeados da pasta Logo Transparente e implemente com impacto direto. Utilize `PATTERN PNG` (marca d'água sutil) injetada na camada global do background sem interferir na leitura (opacity).
- [ ] **Task 4: Fase Quality - Integrity & A11y Gate AIOX** → Obrigatoriamente rodar:
      - `npm run typecheck` e `npm run lint` para checar regras de código.
      - **A11y-check**: Validar contraste (WCAG AA minimum) para garantir legibilidade dos textos e formulários sobre as novas cores inseridas nos modos Light & Dark.

## Done When
- [ ] Todo HEX/CSS foi extraído e implementado perfeitamente dos assets.
- [ ] Contraste visual no Light/Dark Mode passou pelo pipeline de WCAG AA (*Accessibility Check*).
- [ ] Nenhum componente react/TSX teve sua estrutura de UX alterada pelas modificações.
- [ ] Apresentação visual aprovada com alto "Shock Value" para amanhã, e a base de código contínua livre de "Magic Numbers/Colors".
