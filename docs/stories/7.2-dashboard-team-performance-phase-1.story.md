## Notas Técnicas

### Component Architecture

```typescript
// Hierarchy (Atomic Design)
Dashboard Operações
├─ Tabs (Principal | Fluxo | Performance)
└─ Performance Tab Content
   ├─ PeriodSelector (period: 'semanal'|'mensal'|...)
   ├─ TeamFilter (team: 'minha_equipe'|'todos')
   ├─ AdvancedFilters (status, completion range, search)
   ├─ ResponsablePerformanceTable
   │  ├─ Column headers (sortable)
   │  ├─ Table body (paginated 20/page)
   │  ├─ Pagination controls
   │  └─ CSV export button
   └─ ResponsableDetailModal
      ├─ Selected person metrics
      ├─ Sparkline chart
      └─ Breakdown by project
```

### Data Flow

1. usePerformanceData hook fetches PerformanceMetrics[] from API
2. PeriodSelector + TeamFilter determine query parameters
3. Server action (fetchPerformanceMetrics) queries projects + project_histories
4. Calculates aggregated metrics:
   - total_movements = COUNT(project_histories)
   - tempo_medio = AVG(project_tempo_permanencia.dias_na_fase)
   - projects_completed = COUNT(WHERE status = 'concluído')
   - lead_time_medio = AVG(delivery_date - start_date)
5. ResponsablePerformanceTable renders sorted + paginated results

### Performance Optimization

- Data cached with TanStack Query (stale-while-revalidate)
- Server-side aggregation (heavy lifting in API)
- CSV export generates on-demand (no pre-generation)
- Pagination (20 items) prevents table bloat
- Memoization of sort/filter logic

---

## Architecture Decision

- **Component Composition:** Atomic design (selector > filters > table > modal)
- **Data Fetching:** Server actions for aggregation, TanStack Query for client caching
- **Sorting:** Client-side (full data loaded, UI updates instantly)
- **Filtering:** Server-side for performance period, client-side for quick filters
- **Export:** CSV generation server-side, download as blob
- **Accessibility:** Full keyboard nav + ARIA labels per WCAG AA
