## Database & Migrations

### Q1: Migration 066-070 failed during deployment

**Symptom:** Deployment fails, logs show "Migration XXX failed"

**Root Causes:**
1. Previous migration didn't complete (check `migrations` table)
2. Existing column/table conflicts
3. RLS policy preventing schema changes
4. Constraint violation

**Solution:**

```bash
# 1. Check what's in the migrations table
SELECT name FROM migrations WHERE name LIKE '06%' ORDER BY name DESC;

# 2. Check which tables exist
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public'
AND table_name LIKE 'org_%';

# 3. If migration is stuck, check for locks
SELECT pid, usename, query FROM pg_stat_activity
WHERE query LIKE '%ALTER TABLE%' OR query LIKE '%CREATE TABLE%';

# 4. If locked, kill the session (admin only)
SELECT pg_terminate_backend(pid) FROM pg_stat_activity
WHERE pid <> pg_backend_pid()
AND usename = 'postgres';

# 5. Re-run migration in Supabase CLI
supabase db push
```

**Prevention:**
- Apply migrations in order (don't skip)
- Never run migrations manually (use Supabase CLI)
- Test in staging before production

```sql
SELECT EXISTS(

```

### Q3: RLS policy blocking inserts on new tables (066-070)

**Symptom:** "new row violates row-level security policy"

**Root Causes:**
- RLS policy not recognizing new tables
- tenant_id mismatch
- Old RLS policy blocking new columns

**Solution:**

```sql
-- Check RLS policies on new tables
SELECT tablename, policyname, qual
FROM pg_policies
WHERE tablename IN (
  'org_activity_systems',
  'org_process_slas',
  'org_activity_templates',
  'org_process_versions'
);

-- Verify tenant_id in payload matches user's tenant
-- Should see RLS for each table

-- If missing, enable RLS and recreate policies
ALTER TABLE org_activity_systems ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can see own tenant's activity systems"
  ON org_activity_systems
  FOR SELECT
  USING (tenant_id = (SELECT tenant_id FROM profiles WHERE id = auth.uid()));

-- Re-test insert
INSERT INTO org_activity_systems (activity_id, system_id, tenant_id, usage_context)
VALUES ($1, $2, $3, $4);
```

**Verify tenant_id in code:**
```typescript
// In server action
const ctx = await getAuthContext();
// Ensure all inserts include: tenant_id: ctx.tenantId
const { error } = await ctx.supabase
  .from('org_activity_systems')
  .insert({ activity_id, system_id, tenant_id: ctx.tenantId });
```

### Q8: "Cannot update activity: responsible_roles type mismatch"

**Symptom:** Error when saving responsible roles

**Root Causes:**
1. Sending array of objects instead of strings
2. Null value instead of empty array
3. Type casting issue
4. JSONB validation failure

**Solution:**

```typescript
// ❌ WRONG (objects)
const roles = [
  { name: 'gerente', id: '123' },
  { name: 'analista' }
];
await updateActivityAction(id, { responsible_roles: roles });

// ✅ CORRECT (strings)
const roles = ['gerente', 'analista_senior'];
await updateActivityAction(id, { responsible_roles: roles });

// Ensure type in component:
const [roles, setRoles] = useState<string[]>([]);  // ← string array

// In ResponsibleRolesInput
onRolesChange={(newRoles: string[]) => {
  setRoles(newRoles);  // ← newRoles should be string[]
}}

// When submitting:
await updateActivityAction(activityId, {
  responsible_roles: roles  // ← Already string[]
});
```

### Q9: "Usuário não autenticado" error on every action

**Symptom:** All server actions return auth error

**Root Causes:**
1. Session expired
2. Auth cookies missing
3. User not logged in
4. Token refresh failed

**Solution:**

```typescript
// 1. Check if user is logged in
const { data: { user }, error } = await supabase.auth.getUser();
if (!user) {
  // User not authenticated
  router.push('/login');
  return;
}

// 2. Verify session is valid
const { data: { session } } = await supabase.auth.getSession();
if (!session) {
  console.log('Session expired, refresh token');
  // Supabase auto-refreshes, but can manually trigger:
  await supabase.auth.refreshSession();
}

// 3. Check cookies in browser
// DevTools → Application → Cookies
// Should have: sb-access-token, sb-refresh-token

// 4. Clear cookies and re-login
// Settings → Clear site data
// Then: window.location.href = '/login'

// 5. Test in new incognito window to rule out stale cache
```

## Performance & Optimization

### Q11: Dashboard loading slowly (>2 seconds)

**Symptom:** Organization view slow, many spinner states

**Root Causes:**
1. Parallel requests (should be sequential)
2. Missing React Query cache
3. Large dataset without pagination
4. Network waterfall (dev tools shows slow responses)

**Solution:**

```typescript
// 1. Enable React Query caching
const { data, isLoading } = useQuery({
  queryKey: ['areas', tenantId],
  queryFn: () => fetchAreasAction(tenantId),
  staleTime: 5 * 60 * 1000,  // ← Cache for 5 minutes
  gcTime: 10 * 60 * 1000,    // ← Keep in memory for 10 min
});

// 2. Prefetch related data
const queryClient = useQueryClient();
queryClient.prefetchQuery({
  queryKey: ['nuclei', areaId],
  queryFn: () => fetchNucleiAction(areaId)
});

// 3. Paginate large lists
const [page, setPage] = useState(0);
const { data } = useQuery({
  queryKey: ['activities', processId, page],
  queryFn: () => fetchActivitiesAction(processId, {
    limit: 20,
    offset: page * 20
  })
});

// 4. Profile network requests
// DevTools → Network tab
// Sort by Duration (slowest first)
// Identify bottleneck actions and optimize DB queries

// 5. Example: Batch load related entities
// Instead of:
// 1. Load areas (200ms)
// 2. Load nuclei (300ms)
// 3. Load processes (400ms)

// Use:
// 1. Load areas with nuclei count (300ms)
// 2. Load processes with routine count (400ms)
// Total savings: 200ms
```

### Q14: Health check showing RLS compliance < 100%

**Symptom:** `npm run health` shows "RLS compliance: 85%"

**Root Causes:**
1. New table created without RLS
2. RLS policies deleted
3. Policy update incomplete
4. New column not covered by policy

**Solution:**

```bash
# 1. Run health check
npm run health
# Look for: RLS compliance score

# 2. Check which tables are missing RLS
SELECT tablename FROM pg_tables
WHERE schemaname = 'public'
AND NOT EXISTS (
  SELECT 1 FROM pg_policies WHERE pg_policies.tablename = pg_tables.tablename
);

# 3. Enable RLS on missing tables
ALTER TABLE org_activity_systems ENABLE ROW LEVEL SECURITY;
ALTER TABLE org_process_slas ENABLE ROW LEVEL SECURITY;
-- etc for all tables

# 4. Create default RLS policies
CREATE POLICY "users see own tenant data"
  ON org_activity_systems
  FOR SELECT
  USING (tenant_id = (SELECT tenant_id FROM profiles WHERE id = auth.uid()));

# 5. Re-run health check
npm run health
# Should now show: RLS compliance: 100% ✅
```
