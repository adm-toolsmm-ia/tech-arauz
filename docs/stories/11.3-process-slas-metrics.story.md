## 🏗️ Architecture

### SQL Migration

```sql
-- Migration 068: Create Process SLAs & Metrics tables
-- Story 11.3: Process SLAs & Metrics

-- SLA DEFINITIONS
CREATE TABLE IF NOT EXISTS public.org_process_slas (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
  process_id UUID NOT NULL REFERENCES public.org_processes(id) ON DELETE CASCADE,
  metric_name TEXT NOT NULL,
  target_duration_days INTEGER NOT NULL,
  warning_threshold_pct DECIMAL(5,2) DEFAULT 80,
  critical_threshold_pct DECIMAL(5,2) DEFAULT 95,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(tenant_id, process_id, metric_name)
);

CREATE INDEX idx_org_process_slas_tenant ON public.org_process_slas(tenant_id);
CREATE INDEX idx_org_process_slas_process ON public.org_process_slas(process_id);

-- METRICS (AGGREGATED)
CREATE TABLE IF NOT EXISTS public.org_process_metrics (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id UUID NOT NULL REFERENCES public.tenants(id) ON DELETE CASCADE,
  process_id UUID NOT NULL REFERENCES public.org_processes(id) ON DELETE CASCADE,
  period_start DATE NOT NULL,
  period_end DATE NOT NULL,
  metric_name TEXT NOT NULL,
  avg_duration_days DECIMAL(10,2),
  compliance_pct DECIMAL(5,2),
  instances_count INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE(tenant_id, process_id, metric_name, period_start, period_end)
);

CREATE INDEX idx_org_process_metrics_tenant ON public.org_process_metrics(tenant_id);
CREATE INDEX idx_org_process_metrics_process ON public.org_process_metrics(process_id);
CREATE INDEX idx_org_process_metrics_period ON public.org_process_metrics(period_start, period_end);
```

## 📝 Dev Notes

- **SLAs vs Metrics:** SLAs are configuration (what we expect); Metrics are observation (what happened)
- Period should align with reporting cycles (weekly/monthly)
- Compliance % = (instances_meeting_target / total_instances) * 100
- Can have multiple metrics per process (e.g., "completion_time", "quality_score")
- No seed data — populated by admin or background job
