## Overview

All organization components follow React patterns: TypeScript props, controlled/uncontrolled state, accessibility-first (WCAG AA), and integration with Server Actions for mutations.

**Key Patterns:**
- Props typed with interfaces
- Server actions called via `startTransition()` for optimistic updates
- Storybook stories for isolated testing (40+ stories)
- A11y tested with jest-axe (100% WCAG AA)
- Dark mode support via Tailwind `dark:` class

### 3. **Data Input & Forms**

#### `OrgEntityFormSheet`
- **Purpose:** Generic create/edit form for org entities
- **Props:**
  - `isOpen: boolean`
  - `onClose: () => void`
  - `entityType: 'area' | 'nucleus' | 'process' | 'routine' | 'activity' | 'system' | ...`
  - `entity?: Entity` (if editing)
  - `parentId?: string` (if creating child)
  - `onSuccess?: (entity: Entity) => void`
- **Behavior:**
  - Renders dynamic form based on entityType
  - Validates via TanStack Form + Zod schemas
  - Server action called on submit
  - Shows loading state + error toast
  - Optimistic updates via React Query
- **Accessibility:** WCAG AA (labels, error messages, keyboard nav)
- **Storybook:** 8 stories (area form, process form, activity form, edit, error states, responsive)

#### `ResponsibleRolesInput` (EPIC 11.1)
- **Purpose:** Advanced role tagging input with autocomplete + validation
- **Props:**
  - `roles: string[]`
  - `onRolesChange: (roles: string[]) => void`
  - `availableRoles?: string[]` (autocomplete suggestions)
  - `maxRoles?: number` (limit count)
  - `readonly?: boolean`
- **Features:**
  - Autocomplete suggestions (queried from DB or local)
  - Add via input + Enter
  - Remove via X button
  - Duplicate prevention
  - Keyboard navigation (arrows, backspace)
- **Accessibility:** WCAG AA (ARIA combobox, keyboard nav, screen readers)
- **Storybook:** 5 stories (empty, populated, autocomplete, readonly, disabled)
- **Tests:** 12 unit tests + jest-axe a11y test

#### `ActivitySystemsModal` (EPIC 11.2)
- **Purpose:** Modal for managing activity-system M:M relationships
- **Props:**
  - `isOpen: boolean`
  - `onClose: () => void`
  - `activityId: string`
  - `onSuccess?: () => void`
- **Features:**
  - List current systems linked to activity
  - Search/filter available systems to add
  - Add new system (with usage_context: data_entry | lookup | reporting)
  - Remove system (confirmation)
  - Usage context editing (inline)
- **Server Actions:** getActivitySystemsAction, addActivitySystemAction, removeActivitySystemAction
- **Accessibility:** Modal focus trap, ARIA labels
- **Storybook:** 4 stories (empty, populated, adding, removing)

#### **Specialized Inputs**

## 🔄 State Management

### React Query (TanStack Query)
- **Usage:** Data fetching + caching for org entities
- **Pattern:**
  ```typescript
  const { data, isPending } = useQuery({
    queryKey: ['areas', areaId],
    queryFn: () => fetchAreaAction(areaId),
    staleTime: 5 * 60 * 1000, // 5 min
  });
  ```
- **Mutations:** `useMutation()` for server actions with optimistic updates
  ```typescript
  const mutation = useMutation({
    mutationFn: (updates) => updateAreaAction(areaId, updates),
    onSuccess: (data) => queryClient.invalidateQueries(['areas']),
  });
  ```

### Zustand (Client State)
- **Usage:** UI state (modals, drawer visibility, selected filters)
- **Example:**
  ```typescript
  const { isOpen, open, close } = useOrgModalStore();
  ```

### React Hook Form + TanStack Form
- **Usage:** Form state + validation (OrgEntityFormSheet, ResponsibleRolesInput)
- **Validation:** Zod schemas per entity type

## 🚀 Performance Optimizations

1. **Code Splitting:** Each cockpit imported via React.lazy()
2. **Virtualization:** Lists with 1000+ items use react-window
3. **Memoization:** `React.memo()` for expensive renders
4. **Image Optimization:** Next.js Image component for logos/icons
5. **CSS-in-JS:** Tailwind with PurgeCSS for minimal bundle

**Bundle Impact:**
- Organization components: 87.7 kB (shared JS)
- Code split per route

---

## 🔐 Security & Validation

1. **Input Validation:** Zod schemas on all forms
2. **XSS Prevention:** React escaping + DOMPurify for user content
3. **CSRF:** Next.js built-in CSRF tokens
4. **RLS:** All mutations go through server actions (backend validates tenant_id)
5. **Sanitization:** JSONB fields validated before save
