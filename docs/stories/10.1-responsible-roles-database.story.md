### Migration Pattern (065_add_responsible_roles_to_resources.sql)

```sql
-- Seguir padrão existente de org_areas, org_nuclei, org_processes
ALTER TABLE public.org_suppliers
ADD COLUMN responsible_roles JSONB DEFAULT '[]' NOT NULL;

CREATE INDEX idx_org_suppliers_responsible_roles_gin
ON public.org_suppliers USING GIN(responsible_roles);

COMMENT ON COLUMN public.org_suppliers.responsible_roles
IS 'Array of roles responsible for managing this supplier (e.g., ["vendor_manager", "procurement_lead"])';
```

## Architecture Decision

- **Schema Extension:** JSONB column com DEFAULT '[]' para backward compatibility
- **Indexing:** GIN index para performance de queries com containment operators
- **Type Safety:** Strict typing em TypeScript — `string[]` only
- **Action Pattern:** Seguir padrão existente de createX/updateX pattern
- **Backward Compatibility:** Existing records carregam com responsible_roles = []

**Padrão Consistente:** Este story segue exatamente o padrão de colunas JSONB em org_areas, org_nuclei, org_processes, org_routines — sem inovação, apenas replicação em 3 novas tabelas.

**Performance:** GIN indexes habilitam JSON containment queries (~milliseconds) para queries como:
